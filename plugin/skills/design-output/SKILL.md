# 디자인 제작 (결정로그 D31)

DESIGN.md 의 값만 쓴다. 새 색·글꼴이 필요하면 DESIGN.md 를 먼저 고치고 보고에 적는다.

## 공통: 렌더해서 그림으로 본다

코드를 보고 판정하지 않는다. 그림에 보이는 문제는 진짜 문제다.
- .pptx·.docx: `node C:/ainsof/work/design/tools/render.mjs <파일>` → 같은 폴더의 PDF 를 Read 로 연다(쪽마다 그림으로 보인다). LibreOffice 로 그린 것이라 실제 PowerPoint·Word 와 글꼴 폭이 조금 다를 수 있다고 보고에 적는다
- HTML: `node C:/ainsof/work/design/tools/serve.mjs <폴더>`(백그라운드) → 390px(휴대폰)·1440px(웹) 스크린샷
- 먼저 볼 것: 글자가 상자·쪽 밖으로 넘침, 겹침, 잘림, 빈 자리표시("[수치]", "TODO", lorem). 그다음 위계·정렬·여백
- 고치고 다시 렌더한다. 같은 결과물에 최대 3번. 바꾼 쪽만 다시 본다
- 하지 않은 검사는 "못 함"으로 적는다

## 앱·웹 화면

- 결과: `docs\design\<화면>.md` 명세(구성·상태·문구·토큰 이름) + 확정 시안 HTML. 실제 앱 코드는 개발봇이 쓴다
- 상태를 빠뜨리지 않는다: 처음 로딩, 빈 상태, 오류, 권한 거부
- 누르는 곳 44px 이상, 대비 4.5:1, 가로 스크롤 금지(390px에서 확인)
- 아이콘은 SVG. 이모지를 아이콘 대신 쓰지 않는다

## 캐릭터 (픽셀 스프라이트)

- 기본 몸 틀 1벌을 먼저 잘 찍고, 캐릭터마다 설정표 한 줄(팔레트·무늬 마스크·귀·꼬리·소품 겹치기)로 바꾼다. 캐릭터마다 따로 찍지 않는다(토큰 절약)
- 픽셀은 글자 격자(한 글자 = 한 칸, 팔레트 번호)로 코드에 적고, 캔버스에 그려 PNG 로 뽑는다. 크기는 한 판(예: 32×32)으로 통일하고 안티에일리어싱·흐림 없이 칸에 딱 맞춘다(`image-rendering: pixelated`)
- 방향: 앞·뒤·옆 3벌을 찍고 반대쪽 옆은 좌우 뒤집기. 동작: 숨쉬기(1칸 위아래)·걷기는 다리 칸만 바꾼 프레임으로
- 캐릭터 시트: 앞·옆·뒤와 동작 프레임을 4배로 키워 한 장에 모아 본다(`serve.mjs` + 스크린샷). 고칠 때는 그 한 장만 다시 본다
- 사진을 바탕으로 할 때는 사진의 특징(무늬 위치·색·눈색·체형)을 표로 먼저 적고, 시트와 표를 대조한다
- 남의 스프라이트·타일을 가져오지 않는다. 팔레트는 DESIGN.md 의 색만

## 토스 미니앱

- `ait:design` 스킬을 먼저 따른다. 그 스킬의 판정이 이 문서와 다르면 그쪽이 이긴다
- 꼭 지키는 바닥: 11px 이하 글자 없음(다 그린 뒤 전체 확인), 본문 15px 이상, 누르는 곳 44px, 하단 고정 버튼 아래 34px 여백, 꺾쇠는 `>` 글자가 아니라 SVG, 상단 내비게이션 바는 그리지 않음(토스가 붙인다), 한글 `word-break: keep-all`
- 토스 블루(#0064FF 계열)를 주 색으로, Toss Product Sans 를, 토스 로그인 화면 구성을 쓰지 않는다

## 발표 (.pptx, pptxgenjs)

- 장마다 메시지 하나. 제목은 그 메시지 문장으로 쓴다
- 제목 36~44pt, 본문 14~16pt, 어떤 글자도 9pt 미만 금지. 바깥 여백 0.5인치 이상
- 한글은 줄당 글자 수를 영어의 절반으로 잡고 상자 크기를 정한다
- 차트는 PowerPoint 차트(`addChart`)로 넣는다. 그림으로 굽지 않는다. 발표자 메모는 `addNotes` 로
- 슬라이드 전체를 그림 한 장으로 만들지 않는다(편집할 수 없게 된다)
- 파일이 깨지는 것: 색 값에 `#` 을 붙이거나 8자리로 쓰기, 옵션 객체 하나를 여러 `add*` 에 같이 쓰기(라이브러리가 객체를 바꿔 놓는다), 그림자 offset 음수, 누적 막대 차트의 데이터 레이블 `outEnd`

## 문서 (.docx, docx 라이브러리)

- 기본 A4. 제목은 `HeadingLevel` 로(목차가 된다), 목록은 numbering 설정으로(• 글자 금지), 줄바꿈은 문단을 나눠서(`\n` 금지)
- 표: 표 전체 `columnWidths` 와 칸마다 `width` 를 둘 다 DXA 로. 칸 배경은 `ShadingType.CLEAR`(SOLID 는 검게 나온다)
- 같은 줄 오른쪽 정렬(이름 ……… 2024.03)은 탭 정지로. 점·공백으로 채우지 않는다

## 이력서

카드에 서류형인지 디자인형인지 적혀 있어야 한다. 없으면 기획 단계에서 물었어야 한다.
- 서류형(.docx): 1단, 표·글상자·머리글/바닥글에 중요한 내용 금지, 그림·막대 그래프 금지, 표준 섹션 이름(경력·프로젝트·학력·자격), 본문 10pt 이상. 채용 시스템이 글자를 그대로 읽게 한다
- 디자인형(.docx + PDF): 2단·강조색 허용. 글자는 모두 진짜 텍스트로(그림 안의 글자 금지). PDF 는 render.mjs 로 뽑는다
- 둘 다: 원고의 숫자·기간·기관명만 쓴다. 없는 값은 `[확인]` 으로 남긴다
