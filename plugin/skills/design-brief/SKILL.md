# 디자인 기획 (결정로그 D31)

순서를 건너뛰지 않는다. 6단계가 끝나면 멈추고 `status: needs_approval` 로 돌려준다.

## 1. 기획서 `brief.md`

꼭 채울 4칸. 카드에 없으면 추측하지 말고 "CEO가 정할 것"에 적는다.
- 무엇: 만드는 것과 분야(앱·웹·토스 미니앱·발표·문서·이력서 서류형·이력서 디자인형)
- 누구: 보는 사람
- 목적: 보고 나서 그 사람이 할 행동 한 가지(예: "가입 버튼을 누른다", "면접에 부른다")
- 형식: 결과 파일(HTML 시안·화면 명세 / .pptx / .docx / .docx+PDF)과 크기(A4, 16:9, 휴대폰 390px 등)

그리고 쓴다.
- 이 주제에만 있는 것 8~12개(소재·말투·색이 나올 만한 실제 물건). 경쟁사에도 그대로 맞는 것은 빼고 다시 찾는다.
- 내가 읽은 방향 한 줄. 모호하면 묻지 말고 읽은 대로 적고 `[가정]` 을 붙인다. 진짜 막히는 것만 묻는다(최대 2개).

## 2. 레퍼런스 `refs.md`

### 자동 수집 (토큰 절약: 캡처는 파일로, 봇은 모아 보기 한 장만 본다)

1. 검색어는 기획서에서만 뽑는다: "무엇·누구·목적"과 "이 주제에만 있는 것"에서 한국어 2개 + 영어 1개. 기획서에 없는 말로 넓히지 않는다
2. 수집처
   - 앱: `--appstore "<검색어>"` (Apple 공식 검색 API, 앱 스크린샷)
   - 웹: Awwwards 목록 페이지를 브라우저로 한 번 열어 기획서와 맞는 수상작의 **실제 사이트 주소**를 `urls.txt` 에 적고 `--urls urls.txt`
   - 토스 미니앱: 토스 공식 문서의 예시 화면 주소를 `--urls`
   - Pinterest·Dribbble·Behance·Mobbin 은 약관상 봇이 열 수 없다. 넣지 않는다
3. 실행: `node C:/ainsof/work/design/tools/capture.mjs <카드폴더>/refs --appstore "<검색어>" --urls urls.txt [--mobile]` → `refs/sheet.png` 한 장만 Read 로 본다. 낱장은 꼭 필요한 것만 연다
4. 걸러내기: sheet.png 의 번호마다 `refs.md` 에 한 줄씩 "쓸 것 / 뺄 것 · 기획서의 어느 칸과 맞나 · 무엇을 빌리나(구성·여백·위계·색 비율)"를 적는다. 이유를 못 대면 뺀다
5. 기준
   - 쓸 것의 **절반 이상**은 같은 분야나 가까운 분야(예: 식물 앱이면 식물·정원·건강 관리·생활 기록)
   - 다른 분야는 "무엇을 빌리나"가 구성·위계일 때만. 그 분야의 색·그림·문구는 가져오지 않는다
   - 쓸 것이 5개 미만이면 검색어를 바꿔 **한 번만** 더 모은다. 그래도 모자라면 모자란 채로 보고한다
6. CEO가 준 캡처(`refs\` 의 다른 파일)는 이 수집과 따로 Read 로 보고 같은 형식으로 적는다

### 그 밖의 근거

- 공식 가이드: 토스(`developers-apps-in-toss.toss.im`, 문서 MCP), Apple HIG(`developer.apple.com`), Material(`m3.material.io`), 웹 접근성(`www.w3.org`)
- 결과물에 넣을 그림: Openverse, Wikimedia Commons, 시카고 미술관(artic.edu), 메트(metmuseum.org)의 상업 이용 가능한 라이선스만. 출처·라이선스·작가를 적는다

레퍼런스는 증거로만 쓴다. 화면·문구·로고를 옮기지 않는다. 앱 스크린샷·사이트 캡처는 우리 결과물에 넣지 않는다(참고용). 남의 브랜드처럼 보이게 하자는 요청은 만들기 전에 멈추고 CEO에게 확인한다.

## 3. 디자인 규격 `DESIGN.md`

Google DESIGN.md 형식(YAML 토큰 + 이유를 적은 글)으로 쓴다. 섹션 순서: Overview → Colors → Typography → Layout → Elevation & Depth → Shapes → Components → Do's and Don'ts.
- 색 4~6개, 이름과 hex. 하나가 화면의 60~70%를 차지하고, 보조 1~2개, 강조 1개
- 글꼴: 한글은 받는 사람 PC에 있는 것(Windows 기본 "맑은 고딕")을 기본으로 한다. 다른 글꼴은 CEO가 설치·포함을 확인한 경우만
- 크기 하한: 앱·웹 본문 15px 이상, 어떤 글자도 12px 미만 금지(토스는 11px 이하 절대 금지). 발표 본문 14pt 이상, 최소 9pt. 문서 본문 10pt 이상
- 간격 단위 하나(예: 4px 또는 8px 배수)
- 검사: `npx designmd lint DESIGN.md` 를 디자인 폴더에서 돌려 오류 0, 대비 경고 0(4.5:1). 결과 줄을 보고에 옮긴다

## 4. 흔한 AI 디자인과 대조

계획을 아래 목록에 하나씩 대 본다. 걸린 것은 고치고 "무엇을 왜 바꿨나"를 brief.md 끝에 적는다. 카드가 그 방향을 직접 원하면 카드가 이긴다.
- 크림·베이지 바탕 + 세리프 제목 + 테라코타 강조 / 검은 바탕 + 형광 초록·주황 하나 / 보라·인디고·네온 그라데이션
- 똑같은 둥근 카드 3개 나열, 제목 위 작은 대문자 라벨(아이브로우), 01·02·03 번호 매기기, 버튼 글자 끝 "→"
- 발표: 제목 아래 강조선, 장식용 색 띠, 제목+글머리표만 있는 기본 슬라이드
- 지어낸 지표("만족도 98%"), 뜻 없는 말("혁신적인", "새로운 차원의", "Seamless")
- 이 색을 전혀 다른 주제에 옮겨도 어울린다면 덜 정한 것이다

## 5. 시안 2~3개

같은 화면(또는 같은 슬라이드 1장·같은 문서 첫 장)에 **성격이 다른** 방향을 입힌다. 색만 바꾼 것은 시안이 아니다.
- HTML: `drafts\A.html` 처럼 파일 하나씩. 받은 실제 문구를 쓰고 lorem 은 쓰지 않는다. `node C:/ainsof/work/design/tools/serve.mjs <폴더>`(백그라운드) 로 띄워 `http://localhost:4173/A.html` 을 열고 스크린샷(휴대폰 390px, 웹이면 1440px도)
- Stitch: DESIGN.md 를 `create_design_system_from_design_md` 로 올리고 `generate_variants` 로 뽑아도 된다. 화면 프롬프트에는 색·글꼴을 다시 쓰지 않는다(규격에 있으므로). Stitch 는 월 한도가 있어 시안 비교에만 쓴다
- 시안마다 한 줄 성격("넓은 여백과 큰 숫자 하나", "사진 위주")을 적는다

## 6. 승인 요청

brief.md, refs.md, refs/sheet.png, DESIGN.md, 시안 스크린샷 경로를 결과 형식대로 돌려준다. "CEO가 정할 것"에는 고를 시안과 [가정] 중 확인이 필요한 것만 적는다. `status: needs_approval`.
