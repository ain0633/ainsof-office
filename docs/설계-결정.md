# 설계 결정과 실패 기록

이 저장소를 평가하거나 고쳐 쓰려는 개발자를 위한 문서입니다. 무엇을 왜 골랐고, 무엇을 버렸고, 어떤 대가를 치르는지 적었습니다.

## 설계 결정

### 1. 안전 판정은 AI가 아니라 코드가 한다

- **문제:** 봇이 웹 글을 읽으면 그 안의 지시에 속을 수 있습니다.
- **버린 것:** 보안 담당 봇을 두거나, 봇이 위험한지 스스로 판단해 묻게 하는 방식. 판정하는 쪽도 같은 방식으로 속을 수 있습니다.
- **고른 것:** 모든 도구 호출을 훅으로 가로채 규칙표로 판정합니다. 결과는 통과, 사람에게 묻기, 금지 셋입니다.
- **대가:** 명령의 글자를 보는 수준이라 변형된 명령은 놓칠 수 있습니다. 그래서 단단한 설치는 봇 전용 Windows 계정과 NTFS 권한을 한 겹 더 둡니다. 네트워크 차단은 아직 없습니다.

### 2. 역할은 필요한 만큼만 나눈다

- **문제:** 역할을 늘릴수록 호출이 늘고, 넘길 때마다 맥락이 줄어듭니다.
- **고른 것:** 봇을 나누는 기준을 권한 분리, 채점 독립성, 맥락 초과 셋으로 제한했습니다. 앞뒤가 이어지는 일은 한 봇에게 통째로 맡깁니다.
- **대가:** 봇이 일곱까지 늘었지만, 일을 넘기는 지점마다 기준과 양식을 관리해야 합니다.

### 3. 만든 봇은 자기 결과를 채점하지 않는다

- **문제:** 만든 쪽의 "다 됐습니다"는 근거가 되지 못합니다.
- **고른 것:** 개발 결과는 QA봇이 실행으로, 조사 결과는 검수봇이 원문 대조로 확인합니다. 채점 봇에게는 만든 봇의 설명을 넘기지 않고, QA봇은 코드를 고칠 수 없습니다.
- **대가:** 단계와 호출이 늘어납니다. 고치는 기회는 한 번으로 묶어 끝없는 반복을 막고, 그래도 안 되면 사람에게 넘깁니다.

### 4. 사람은 세 곳에만 들어간다

- **고른 것:** 지시, 시작 승인, 최종 결정. 그 사이에는 게이트가 위험한 것만 올립니다.
- **근거:** 2026-10-14 ~ 10-24 기록에서 도구 호출 815건 중 사람이 직접 본 것은 49건이었습니다.
- **대가:** 접수 카드를 한 번 더 읽어야 해서, 아주 작은 일에는 번거롭습니다. 질문과 상태 확인은 카드 없이 바로 답합니다.

### 5. 코드 리뷰에 다른 회사 모델을 쓴다

- **문제:** 같은 회사 모델끼리는 비슷한 실수를 놓칠 수 있다고 봤습니다. 아직 측정한 사실은 아닙니다.
- **고른 것:** 코드리뷰봇은 직접 리뷰하지 않고 Codex를 읽기 전용으로 실행해 결과를 그대로 옮깁니다.
- **대가:** 코드가 OpenAI로 나가고, Codex 안의 동작은 게이트가 보지 못합니다. 그래서 샌드박스 옵션을 바꾸는 인자와 설정 파일 쓰기를 게이트가 막습니다.

### 6. 모델은 봇이 아니라 작업 카드마다 고른다

- **버린 것:** 봇마다 모델을 고정하는 방식, 표준 과제 세트로 실험해 정하는 방식.
- **고른 것:** PM이 크기, 자동 확인, 읽을 양, 명세, 되돌림, 일의 모양을 보고 등급과 생각 깊이를 고릅니다. 모델 이름은 표 한 곳에만 둡니다.
- **규칙:** 등급을 올리는 신호는 QA 불합격이나 검수 오류 같은 바깥 판정뿐입니다. 모델의 자기 확신은 쓰지 않습니다.
- **대가:** 규칙의 숫자는 아직 이 프로젝트에서 검증되지 않았습니다. 카드마다 기록을 남겨 회고에서 봅니다.

## 측정 결과

같은 조사 과제를 봇 회사로 3번, 혼자 일하는 AI로 3번 돌렸습니다. 출처 오류는 둘 다 0건이었고, 평균 비용은 $2.13과 $1.93(API 요금 환산)이었습니다. **팀이 더 잘한다는 증거는 없었습니다.** 과제 1개로 잰 결과라 일반화할 수도 없습니다.

## 실패 기록

- **규칙이 PM에게 닿지 않았습니다.** 공통 규칙을 스킬로 옮겼는데, 메인 세션인 PM에게는 스킬 미리 읽기가 적용되지 않았습니다. 승인 문구가 달라지는 회귀가 나서 되돌렸고, PM이 시작할 때 파일을 직접 읽게 했습니다.
- **Codex 연결은 세 번 만에 됐습니다.** 첫 시도는 봇이 끼워 넣은 `echo`를 게이트가 막았습니다. 둘째는 Codex 샌드박스 계정이 잠긴 작업 폴더에 들어가지 못했습니다. 폴더 권한을 넓히지 않고 샌드박스 방식을 바꿔 해결했습니다. 봇은 우회하지 않고 멈췄고, PM은 "지적 없음"이 아니라 "리뷰 없음"으로 보고했습니다.
- **작업 결과가 잘못 기록됐습니다.** 게이트가 PM의 지시문에 적힌 `status: blocked`를 결과로 읽어, 봇이 움직이기도 전에 실패로 기록했습니다. 결과 응답만 읽도록 고쳤습니다.
- **깨진 주소 한 번에 사무실 서버가 꺼졌습니다.** 공개 뒤 점검에서 `/%` 요청으로 재현했습니다. 처리기의 오류를 한곳에서 받도록 고치고 시험을 추가했습니다.

## 아직 모르는 것

- Codex 리뷰는 1건뿐이고 지적이 없었습니다. 실제 문제를 잡는지는 아직 모릅니다.
- 파일이 많은 변경에서 Codex가 충분히 읽는지 확인하지 못했습니다.
- 생산성은 과제 하나로만 쟀습니다.
- 다른 사람이 처음부터 설치해 본 기록이 없습니다.
